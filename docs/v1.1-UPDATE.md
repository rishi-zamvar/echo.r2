# echo.r2 v1.1 — Update Doc (first on-device feedback, 2026-11-12)

Source: Rishi's first real use of TestFlight build 0.1.0 (20261111.2357) against the live Mac stand-in hub.
Status: issues captured; this doc drives a new GSD phase (Phase 5: v1.1 hardening + UI rebuild).

## P0 — Must fix before anything else

### P0-1 echo interactions crash Claude Code in Even Terminal (glasses)
- **Symptom:** some interactions with the echo app crash the Claude Code session Rishi is driving from Even Realities G2 via Even Terminal. Absolute no-go.
- **Evidence so far:** hub log shows app-triggered resumes at 02:52 of two sessions (`d0a9f67b`, no transcript; `28ea96aa`, entrypoint `cli`) — neither is an Even Terminal (`sdk-ts`) session, so take-over/resume of the glasses session is NOT the confirmed path.
- **Leading hypothesis (H1): boot PID sweep kills an unrelated claude process.** On every hub start, `sessions.js` kills stored PIDs from `sessions.json` if the PID is alive and "is claude". Even Terminal spawns a fresh `claude --resume …` process per turn, so PID reuse can make a stale stored PID point at the glasses session's current process → SIGKILL. The hub was restarted many times on 2026-11-11/12 (deploys, key setup, kickstarts).
- **Other hypotheses to rule out:** (H2) global `Stop`/`Notification` http hooks in `~/.claude/settings.json` misbehaving when the hub is down/restarting (docs say non-blocking; verify with Even Terminal's SDK path specifically); (H3) external-session discovery reading `~/.claude/sessions/*.json` or transcripts in a way that races Even Terminal writes (should be read-only — verify no writes/locks); (H4) app "Take over"/"Resume" on a session whose live owner is Even Terminal (guard only checks transcript mtime < 60 s and sessions registry).
- **Fix requirements:**
  1. Hub must NEVER kill a process it did not spawn in the current boot unless the process's full command line contains `--session-id <id>` or `--resume <id>` for that exact stored session id AND its parent is not Even Terminal. Log every kill with pid + matched id (no other args).
  2. Take-over/resume refused for any session whose entrypoint is `sdk-ts`/Even Terminal unless Rishi explicitly force-confirms, and always refused while any live process references that session id (check `ps` command lines, not just mtime).
  3. Global hooks: confirm behaviour with hub down; add `timeout: 2`; consider an opt-out marker so Even Terminal sessions skip echo hooks entirely if implicated.
  4. Reproduction harness: script that drives Even Terminal-like `claude --resume` churn while restarting the hub N times; must show zero external kills.
- **Acceptance:** 50 hub restarts + every app action (open, resume, take over, stop, test push) while an Even Terminal session is mid-turn → Even Terminal session never dies.

### P0-2 Push test fails: `403 BadEnvironmentKeyInToken`
- **Meaning:** the APNs key is restricted to a different environment than the token. TestFlight builds register **production** tokens; the key was likely created as Sandbox-only (or production-only while the token is sandbox).
- **Fix:** in developer.apple.com → Keys → "echo hub" → set environment to **Sandbox & Production** (or create a new key with both), drop the new `.p8` in Downloads, Claude installs it. Also: hub should surface APNs reason strings in plain words in the app ("Push key is sandbox-only — make it Sandbox & Production") and `/health` should report the last APNs error.

## P1 — Core functionality broken / missing

### P1-1 Can't chat back and forth
- Most listed sessions are **external** (started in Terminal/Even Terminal/claude -p) → read-only by design, so the composer is hidden. To Rishi this reads as "chat is broken".
- **Fix direction:** make the model obvious and useful:
  - Clear "Watching — started on <device>" header + one prominent **Continue here** action (safe take-over, subject to P0-1 guards).
  - Hub-owned sessions: verify send works end-to-end on device (input → PTY → transcript → chat bubble). Add an on-device test.
  - New session from phone should be the primary, front-and-center path.

### P1-2 Opening a stopped/ended chat shows nothing
- Stopped/exited/external sessions should open with **full chat history** read from the transcript, even if no PTY is live. Hub needs a history endpoint (or WS replay sourced from the transcript when the in-memory event log is empty, e.g. after hub restart).

### P1-3 Session list is noisy
- Show a **one-line summary** per session (what it's about) — from `ai-title`/first user prompt/last assistant line, or a short generated summary.
- **Hide noise:** one-off `claude -p` runs, sessions with < N turns, stale (> X days) externals → collapsed "Other" section or filter toggle. Promote relevant/active ones.
- **Active vs inactive colour:** running/waiting sessions visually distinct (colour + motion) from done/stopped/external.

### P1-4 Pairing friction
- Code field kept the dash and truncated the code (fixed in hub? no — app bug: strip non-alphanumerics before the 8-char cap).
- **Zero-tap pairing:** if the request comes from a tailnet device whose whois LoginName == owner, hub issues a token without a code (`POST /pair/auto`); app tries it on first launch. Code pairing stays as fallback.

### P1-5 TestFlight friction
- Add `ITSAppUsesNonExemptEncryption = NO` so builds skip export-compliance.
- Release script: keep `-skipPackagePluginValidation`; make `release.sh` failure obvious (it exits 1 — the wrapper misreported).

## P2 — UI/UX rebuild ("looks vibe-coded")
Rishi's verdict: UI is bad, black background disliked, not smooth, wants everything clean, haptic, interactive.
- **Process:** use the installed `impeccable` design skill (critique → shape → polish) plus `swiftui-pro` review. Design against the shared apothecary language (lavender canvas, cream cards, sage) — no black surfaces outside a deliberately styled terminal (terminal gets a light/paper theme option, default light).
- **Requirements:**
  - Smooth: spring animations on navigation, list changes, state chips; no layout jumps; 120 Hz-friendly.
  - Haptics on every meaningful interaction (send, state change arrival, pull-to-refresh, toggle, errors).
  - Clean hierarchy: one-line summaries, clear active/inactive, generous spacing, empty/loading/error states designed (not default).
  - Chat: proper bubbles, markdown, tool rows collapsed by default, typing/working indicator while Claude runs.
- **Rigorous frontend testing:**
  - iOS Simulator runtime now installed → snapshot tests (swift-snapshot-testing, already used in WorkoutCoach) for every screen × light/dark × Dynamic Type sizes.
  - XCUITest flows: pair, list, open session, send, toggle terminal, resume, take over.
  - XcodeBuildMCP screenshot review loop in the simulator for each screen before release.
  - Accessibility audit (VoiceOver labels, contrast).
